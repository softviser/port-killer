# Port Killer

Небольшое приложение для области уведомлений Windows: показывает, какая программа слушает какой порт на этом компьютере, и одним щелчком завершает зависшие серверы разработки.

Когда в следующий раз увидите `EADDRINUSE: address already in use :::3000`, не набирайте в PowerShell `Get-NetTCPConnection -LocalPort 3000 | ... | Stop-Process`, а щёлкните значок в трее и нажмите кнопку ✕ рядом со строкой.

## Загрузка

В каждом выпуске на странице [Releases](https://github.com/softviser/port-killer/releases) есть две сборки. Обе состоят из одного файла, не требуют установки и работают в Windows 10 или 11 (64-разрядной).

| Файл | Размер | Требования |
|---|---|---|
| `PortKiller-<version>-win-x64.exe` | ~66 MB | Нет; .NET встроен |
| `PortKiller-<version>-win-x64-requires-net8.exe` | ~0.2 MB | [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0) (x64) |

Если .NET 8 уже установлен, как на большинстве машин .NET-разработчиков, достаточно маленького файла. Если среды выполнения нет, Windows покажет сообщение со ссылкой для её загрузки.

Исполняемый файл не подписан цифровой подписью, поэтому при первом запуске Windows SmartScreen может показать предупреждение. Чтобы продолжить, выберите **Подробнее > Выполнить в любом случае**. Загрузку можно проверить по файлу `SHA256SUMS.txt`:

```powershell
Get-FileHash .\PortKiller-*.exe -Algorithm SHA256
```

В Windows 11 с включённым **интеллектуальным контролем приложений** неподписанные приложения блокируются сразу, и варианта «Выполнить в любом случае» нет. У Port Killer пока нет цифровой подписи, поэтому на таких компьютерах он не запустится.

## Что она делает

- Группирует прослушиваемые TCP-порты (IPv4 и IPv6) по программам. Инструменты разработки, такие как Node.js, Python, .NET, Docker и PostgreSQL, получают собственные группы вверху списка; всё остальное попадает в «Другие приложения» внизу.
- Кнопка ✕ в конце каждой строки завершает процесс, так же как `Stop-Process -Force` в PowerShell. Прежде чем завершить что-либо, не являющееся инструментом разработки, приложение запрашивает подтверждение.
- Список обновляется каждые 3 секунды. Когда новый порт начинает прослушиваться, вы получаете уведомление Windows; щелчок по нему открывает список.
- Поле поиска фильтрует по порту, имени программы, PID и адресу по мере ввода. Запросы `:3000` и `3000` дают один и тот же результат.
- Интерфейс использует язык отображения Windows (34 языка). Светлая или тёмная тема и акцентный цвет тоже берутся из настроек Windows, а изменения применяются без перезапуска приложения.
- Права администратора не нужны. Приложение может завершать процессы, запущенные под вашей учётной записью.

### Что скрыто

Задача приложения в том, чтобы управлять портами, открытыми во время разработки, а не отключать то, на чём держится работа Windows. Поэтому:

- Порты ниже 1024 (службы Windows, такие как SMB, RPC и HTTP.sys) не показываются.
- Системные процессы, такие как `System`, `svchost`, `lsass`, `services`, `wininit`, `winlogon`, `csrss`, `smss`, `spoolsv`, Windows Defender и индексатор поиска, в списке никогда не появляются.

Список программ, которые считаются инструментами разработки, — это словарь `DevTools` в [`Ports.cs`](src/PortKiller/Ports.cs). Если нужного вам инструмента там нет, добавьте его.

## Использование

При запуске приложения в области уведомлений появляется красный значок «PK».

- **Левый щелчок:** открывает или скрывает список портов.
- **Правый щелчок:** меню с пунктами Показать порты, Обновить, О программе и Выход.

Закрытие окна не завершает приложение, а только скрывает список. Чтобы выйти полностью, выберите **Выход** в меню значка в трее.

| Сочетание клавиш | Действие |
|---|---|
| F5 | Обновить список |
| Ctrl+F | Перейти в поле поиска |
| Delete | Завершить процесс в выбранной строке |
| Esc | Очистить поиск; если поиск пуст, скрыть окно |

![Окно «О программе»](docs/about-light.png)

## Известные ограничения

- Чтобы завершить процесс, запущенный от имени администратора (например, PostgreSQL, установленный как служба Windows), Port Killer тоже должен работать от имени администратора. Иначе он покажет сообщение об ошибке.
- С инструментами, которые перезапускаются сами, например `nodemon`, вы можете получить повторное уведомление о «новом порте» для того же порта, если перезапуск совпадёт с проверкой, выполняемой раз в 3 секунды.
- В тёмной теме полоса прокрутки, появляющаяся, когда список не помещается в окно, остаётся светлой.
- Показываются только TCP-слушатели; UDP-порты не показываются.

## Сборка из исходников

Требования: Windows 10 или 11 и [.NET 8 SDK](https://dotnet.microsoft.com/download).

```powershell
git clone https://github.com/softviser/port-killer.git
cd port-killer

# Run during development
dotnet run --project src\PortKiller

# Single-file exe that also runs on machines without .NET (artifacts\PortKiller.exe)
dotnet publish src\PortKiller -c Release -r win-x64 --self-contained `
    -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
    -p:EnableCompressionInSingleFile=true -p:DebugType=none -o artifacts
```

### Структура проекта

| Файл | Содержимое |
|---|---|
| `Ports.cs` | Чтение прослушиваемых портов, списки инструментов разработки и системных процессов, завершение процессов |
| `TrayApp.cs` | Значок в трее, меню, периодические проверки и уведомления |
| `PortsForm.cs` | Сгруппированная таблица портов, поиск и верхняя панель |
| `AboutForm.cs` | Окно «О программе» |
| `Strings.cs` | Тексты интерфейса на 34 языках |
| `Theme.cs` | Цвета на основе светлой/тёмной темы и акцентного цвета Windows |

### Переводы

Тексты интерфейса находятся в таблице в [`Strings.cs`](src/PortKiller/Strings.cs), по одной строке на язык. Чтобы добавить язык, добавьте его код (например, `"sr"` или `"pt-BR"`) и 13 строк в том же порядке. Если заметите ошибку в переводе, смело создавайте issue или pull request.
